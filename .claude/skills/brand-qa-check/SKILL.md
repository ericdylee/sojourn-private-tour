# Brand QA — 발행 전 교차 검수

이 스킬의 핵심은 "파일이 존재하는가"가 아니라 **"경계면이 어긋났는가"** 다. 각 제작자는 자기 산출물 안에서는 옳게 만든다. 사고는 항상 경계에서 난다 — 카드가 말한 가격과 블로그가 말한 가격이 다르고, 카피는 맞는데 렌더에서 잘리고, 브리프가 UNVERIFIED로 표시한 사실이 SNS에 그대로 나간다.

## 먼저 읽어라

1. `.claude/skills/sojourn-brand-system/SKILL.md` — 모든 판정 기준의 출처
2. `_workspace/01_brief.json` — **팩트 원장. 모든 사실 주장의 대조 기준**
3. `output/cards/*.png`, `output/blog.md`, `output/social.json`

## 검수 원칙

**PNG를 Read 도구로 실제로 열어서 봐라.** HTML 소스만 읽고 판정하지 마라 — 이유: 잘린 글자, 부기에 가려진 워드, 흰 배경 위 흰 텍스트는 전부 렌더 결과에만 나타난다. HTML은 멀쩡한데 이미지는 망가진 경우가 이 파이프라인의 대표 실패다.

**증거 없는 지적을 하지 마라.** 각 지적에 파일 경로와 구체적 위치를 붙여라.

## 검수 항목

### A. 카드뉴스 (이미지를 열고 확인)

| # | 항목 | 판정 기준 |
|---|------|----------|
| A1 | 규격 | 6장 전부 정확히 1080×1080 |
| A2 | 텍스트 잘림 | 의도한 `.bleed-*` 외에 잘린 글자가 없는가. 단어 첫 글자가 잘렸으면 무조건 실패 |
| A3 | 세이프에어리어 | 로고·핸들·페이저·CTA가 사방 72px 안에 있는가 |
| A4 | 하단 가드 | 하단 100px에 의미 있는 텍스트가 없는가 (인스타 그리드 크롭) |
| A5 | 대비 | 배경 대비 텍스트가 읽히는가. 흰 배경 + 흰/샌드 텍스트, 블루 배경 + 블루 계열 텍스트 금지 |
| A6 | 가림 | 부기가 Display 워드를 가려서 못 읽게 만들지 않았는가 |
| A7 | 부기 **라이선스** 규정 | 좌우 반전 없음 / 비율 왜곡 없음(한 축만 늘림 금지) / 부리 노랑·안경 빨강 유지 / 입 벌린 형태 없음 / AI로 생성한 포즈·표정·의상 없음 — 하나라도 위반이면 **BLOCKER** |
| A7b | 저작권 표기 | 부기 등장 카드마다 존재하는가. **그리고 실제로 읽히는가** — 캐릭터나 밴드 위에 겹쳐 안 보이면 표기가 없는 것과 같으므로 BLOCKER. 렌더 PNG를 열어 눈으로 확인하라 |
| A8 | 부기 운영 규칙 | 6장 중 3~5장 등장 / 01에 등장 / 최소 높이 360px / 회전 ±8도 이내 / 얼굴·안경 미가림 |
| A8b | 누끼 | 부기 주변에 흰 사각형 잔상이 없는가. 몸통 외곽이 파먹히지 않았는가 (외곽 훼손은 형태규정 위반이기도 하다) |
| A9 | 세트 일관성 | 6장 나란히 놓았을 때 락업 위치가 동일하고 같은 브랜드로 보이는가 |
| A10 | 색 규칙 | 카드당 배경 1색 + 액센트 1종 / 브랜드 시스템 외 색 없음 / 보라·인디고 없음 |
| A11 | 오탈자 | 영문 스펠링, 고유명사 표기 (Gwangalli, Haeundae, Jagalchi, Gamcheon) |
| A11b | **사진 저작권 표기의 완성 여부** | 화면의 `.photo-credit`은 **축약형**이다(저작자 / 출처 / 라이선스명 / `cropped`). CC BY 4.0은 라이선스 **링크**와 **변형 내역**도 요구하고, 그건 `output/publish_caption.md`에만 있다 — 축약형을 택한 조건이 "발행 시 캡션 동봉"이었다(4회차 N1). 따라서 검수 항목은 두 가지다: ① 화면 크레딧의 라이선스명·`cropped`가 매니페스트의 실제 권리와 맞는가 ② **`publish_caption.md`에 해당 산출물(카드 / 릴스) 절이 있고 현재 쓰는 사진과 일치하는가.** 릴스도 같은 의무를 진다 — 오히려 더 자른다(9:16 추가 크롭 + 확대). 캡션 절이 없거나 사진과 어긋나면 **발행 불가**로 판정하라. CC0 사진은 표기 의무가 없으므로 대상이 아니다 |
| A12 | **이미지가 주장하는 사실** | 사진·개념 이미지 안에 원장에 없는 구체값이 보이는가 — 읽히는 **시계 시각**, 가격표, 인원수, 차량 번호판·등급, 간판·메뉴 문구, 영업시간 표시. 하나라도 있으면 **BLOCKER**(ADR-013). 개념 이미지도 예외가 아니다. 실제 사례: 카드 03에 넣을 시계를 생성했더니 지시하지 않은 9시 10분을 그려 와, 직전에 문장으로 지운 운영시간 주장(B2)이 그림으로 되살아났다 |

### B. 팩트 교차 검증 — 가장 중요

1. 카드 6장 · 블로그 · SNS 3편에서 **사실 주장**(가격, 소요시간, 운영시간, 거리, 인원, 후기)을 전부 뽑아낸다.
   **글자만 보지 마라 — 그림도 주장한다.** 카드 안 이미지에 읽히는 숫자·시각·표지가 있으면 그것도 주장으로 목록에 올린다(A12).
2. 각각을 브리프 `facts`의 `claim`과 대조한다.
3. 판정:
   - 원장에 없음 → **BLOCKER**
   - 원장에 있으나 `source: "UNVERIFIED"` → **BLOCKER**
   - 원장과 값이 다름 → **BLOCKER**
   - 채널 간 값이 서로 다름 (카드 "4 hours" vs 블로그 "5 hours") → **BLOCKER**

숫자가 틀린 투어 광고는 환불·분쟁 사유다. 이 항목은 톤 문제와 급이 다르다.

### C. 링크

`output/` 전체의 URL을 실제로 열어 응답 코드를 확인한다. 200이 아닌 링크가 산출물에 있으면 **BLOCKER**.

정식 랜딩은 `https://www.sojournkorea.net/private-tour`이다. 다음은 **MAJOR**로 처리하라 (링크는 살아있지만 리다이렉트가 한 번 더 끼어 SNS 프리뷰·클릭 추적이 깨질 수 있다):
- `www.`가 빠진 apex URL
- 구 주소 `/tour.html`, `/tour`, `/private-tour.html`

가격 표기가 산출물에 있으면 BLOCKER다. 랜딩 페이지에 가격이 없어 대조할 원본이 없다.

### D. 채널 규격

| 항목 | 기준 |
|------|------|
| 블로그 | 2,700~3,300자 (영문 공백 포함) / 메타 155자 이내 / `/private-tour` 내부 링크 1회 / `[NEEDS FACT]` 잔존 0건 |
| Threads | 500자 이내 / 해시태그 0~2 |
| LinkedIn | 500자 이내 / 해시태그 3~5 / 문단 사이 빈 줄 존재 |
| X | 500자 이내 / 해시태그 0~2 / 첫 포스트가 단독으로 성립 |
| 전 채널 | 세 편에 동일 문장 없음 |

### E. 톤·금지 표현

브랜드 시스템 §6 금지어(`hidden gem`, `must-visit`, `breathtaking`, `nestled`, `vibrant`, `unforgettable journey`)와 브리프 `banned_extra`를 전 산출물에서 검색한다. 한국어 혼입도 확인한다 (이번 캠페인은 영어 단독).

### F. 부기 라이선스

`sojourn-brand-system/references/boogie-usage.md`의 승인 상태 체크박스를 확인한다. **승인완료가 아니면 발행 판정은 무조건 HOLD**다. 내부 시안까지만 허용.

## 판정 등급

| 등급 | 의미 | 처리 |
|------|------|------|
| **BLOCKER** | 발행하면 사고 | 발행 금지. 담당 에이전트에게 반려 |
| **MAJOR** | 브랜드 훼손 | 수정 후 발행 |
| **MINOR** | 개선 권장 | 기록만 하고 발행 가능 |

BLOCKER가 1건이라도 있으면 전체 판정은 **HOLD**다. "카드는 괜찮으니 카드만 발행" 같은 부분 승인을 하지 마라 — 6장·블로그·SNS는 한 캠페인이라 하나가 틀리면 나머지가 그 틀린 사실을 뒷받침한다.

## 출력 — `output/qa_report.md`

```markdown
# QA Report — {campaign_id}
**판정: PASS | HOLD**   BLOCKER {n} · MAJOR {n} · MINOR {n}

## BLOCKER
| # | 파일 | 위치 | 문제 | 담당 | 수정 방향 |

## MAJOR / MINOR
(동일 형식)

## 통과 항목
A1~A11, B, C, D, E, F 중 이상 없던 항목 나열

## 팩트 대조표
| 주장 | 등장 위치 | 원장 대조 | 결과 |
```

## 하지 마라

- HTML만 읽고 카드를 판정하지 마라. 이유: 잘림·가림·대비는 렌더 결과에만 나타난다.
- BLOCKER를 MAJOR로 낮추지 마라. 이유: 검수자가 등급을 무르면 검수 단계 자체가 무의미해진다.
- 산출물을 직접 고치지 마라. 담당 에이전트에게 반려하라. 이유: 검수자가 고치면 아무도 검수하지 않은 코드가 발행된다.
- 지적 없이 PASS를 내지 마라. 통과 항목을 명시적으로 나열해서 무엇을 봤는지 남겨라.
