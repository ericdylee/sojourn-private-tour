# Card News — 주제에서 발행까지 4단계

카드뉴스 6장을 만든다. **네 단계를 순서대로 밟고, 각 단계는 파일을 남긴다.** 파일을 남기는 이유는 격식이 아니다 — 3단계에서 사진이 없다는 것이 드러나면 2단계 기획으로 돌아가야 하는데, 기획이 대화에만 있으면 전부 다시 해야 한다.

| 단계 | 하는 일 | 산출 |
|------|--------|------|
| 1 · 주제 | 무엇에 대한 6장인지 정한다 | `_workspace/02_carousel.json` (topic) |
| 2 · 기획 | 6칸 각각의 문구를 짠다 | 같은 파일 (cards[].copy) |
| 3 · 이미지 | 기획에 맞는 사진을 원장에서 고른다 | 같은 파일 (cards[].photo) |
| 4 · 생성 | HTML 조판 → 렌더 → 육안 확인 | `_workspace/03_cards.html`, `output/cards/*.png` |

한 파일에 세 단계를 누적하는 이유: 어느 카드가 어느 사실에 기대고 어느 사진을 쓰는지가 **한 화면에 보여야** 팩트·라이선스 검수가 가능하다. 흩어 놓으면 대조가 사람 기억에 의존한다.

## 먼저 읽어라

1. `.claude/skills/sojourn-brand-system/SKILL.md` — 컬러·타입·아키타입·톤. **예외 없이 선행 필수.**
2. `docs/UI_GUIDE.md`의 "현재 방향" 절 — 지금 쓰는 포맷이 무엇인지.
3. `assets/carousel-plan.example.json` (이 스킬 번들) — 2·3단계 산출물의 형식. 실제로 만든 감천 세트가 그대로 들어 있다.

## Step 0 — 재실행 판별

무엇을 하는 실행인지 먼저 가른다. 이걸 건너뛰면 "3번 사진만 바꿔줘"에 전체를 갈아엎는다.

```
02_carousel.json 없음                 → 1단계부터
있음 + 특정 카드/요소만 수정 요청     → 해당 단계만. 나머지 카드는 손대지 마라
있음 + 새 주제                        → 기존 세트를 _workspace/cards_prev_{n}/ 로 보존 후 1단계부터
```

손대지 않은 카드를 다시 만들지 마라. 미묘하게 달라지면 이미 통과한 검수가 무효가 된다.

## 1단계 — 주제 선정

**주제는 한 장소, 또는 경계가 분명한 한 소재다. 상품 앵글이 아니다.** 블로그가 "한 편 = 한 장소"로 간 것과 같은 이유다: 사람들이 검색하고 저장하는 것은 동선 최적화가 아니라 장소 이름이다.

주제 후보는 랜딩의 코스에서 나온다 — Gamcheon, Jagalchi·Gukje, Haedong Yonggungsa, Sky Capsule·Gwangalli, Haeundae, Huinnyeoul, Songdo, Taejongdae.

**세 가지를 모두 만족해야 착수한다:**

| 조건 | 확인처 | 왜 |
|------|-------|-----|
| 랜딩 코스에 실제로 있는 곳인가 | `_workspace/01_brief.json` facts | 없는 곳을 홍보하면 약속 위반이다 |
| 팩트 출처가 있는가 | 그 장소의 블로그 발행본, 없으면 확보 계획 | 카드에는 출처를 달 자리가 없다 (2단계 참조) |
| **사진이 5장 이상 있는가** | `assets/photos/manifest.json` | 없으면 3단계에서 전부 무너진다 |

세 번째를 1단계에 두는 것이 이 절차의 핵심이다. 문구를 먼저 짜고 사진을 나중에 찾으면, 사진이 없을 때 **잘 쓴 기획을 통째로 버리게 된다.** 실제로 그렇게 됐다. 사진 재고를 먼저 세면 기획이 가진 것 안에서 시작한다.

후보를 정하지 못하면 **3개를 제안하고 사용자에게 고르게 하라.** 임의로 정하고 진행하지 마라.

## 2단계 — 캐러셀 기획

6칸의 역할은 아래를 기본으로 한다. **블로그의 장소 편 뼈대와 같다** — 같은 장소를 두 채널이 다루는데 뼈대가 다르면 팩트 검증을 두 번 해야 한다.

| # | 역할 | 하는 일 |
|---|------|--------|
| 01 | COVER | 장소 이름 + 이 6장이 무엇을 뒤집을지 예고 |
| 02 | THE TURN | 통념을 교정하는 사실 하나. 이 카드가 세트의 이유다 |
| 03 | WHAT YOU SEE | 실제로 보게 되는 것 |
| 04 | THE ASK | 그 장소가 방문자에게 요구하는 것 |
| 05 | BEFORE YOU GO | 알고 가야 하는 실무 |
| 06 | WITH US | 오퍼. **한 번만** |

역할이 안 맞으면 바꿔도 된다. 다만 **오퍼는 한 장을 넘기지 마라.** 여섯 장 전부가 광고면 저장되지 않는다.

### 카피 규칙

- **헤드라인 2줄.** 각 줄은 Montserrat 800 80px에서 한 줄에 들어가야 한다. 세 줄로 접히면 세트의 리듬이 깨진다 — 크기를 줄이지 말고 단어를 바꿔라.
- **액센트 구절은 카드당 정확히 하나.** 그 카드가 전달하려는 것 하나만 칠한다. 두 개를 칠하면 첫 번째의 값이 반으로 준다.
- **지지문 1~2줄.** 헤드라인이 못 담은 근거를 여기서 준다.
- **영어 단독** (ADR-002). 고유명사는 영문 표기.
- 금지 표현은 브랜드 시스템 §6.

### 팩트 출처 규칙 — 이 절이 이 단계의 핵심이다

**카드에는 출처를 달 자리가 없다.** 블로그는 문장 옆에 링크를 걸 수 있지만 카드는 못 한다. 그래서 카드에 올릴 수 있는 사실은 둘 중 하나여야 한다:

1. **그 장소의 블로그에 이미 출처와 함께 발행된 사실** — 우리가 공개적으로 이미 책임진 문장이다
2. **브리프 `facts` 원장의 서비스 사실** — 전용 차량, 코스 구성 등

둘 다 아니면 쓰지 마라. 쓰고 싶으면 **먼저 블로그에 출처와 함께 실어라.**

**카드에 올리지 않는 것** — 참이어도 올리지 않는다:
- 제3자 가격(입장료·스탬프 지도 등), 운영시간, 소요 시간
- 이유: 바뀌는 값인데 카드는 회수가 안 되고, 출처를 달 자리가 없다. 투어 사업자가 실제로 분쟁에 걸리는 항목이 정확히 이것들이다.

각 카드에 `fact_source`를 적어라. 적을 게 없는 카드는 아직 기획이 안 된 카드다.

### 이미지 의도

카드마다 `image_intent`를 한 줄로 적는다 — "무엇이 찍힌 사진이 필요한가". 3단계의 검색어이자, **문구와 그림이 어긋났는지 판정하는 기준**이다.

## 3단계 — 이미지 선별

`image_intent`마다 `assets/photos/manifest.json`을 검색한다. 결과는 셋 중 하나다.

| 결과 | 처리 |
|------|------|
| **실사진 있음** | 채택. `photo` 키와 `rights` 기록 |
| **없지만 그 카드가 장소를 주장하지 않음** | `slot: concept` AI 생성 허용 (ADR-015). 랜드마크·문자·간판을 프롬프트에서 명시 배제 |
| **없고 그 카드가 장소를 주장함** | 아래 |

세 번째가 이 단계가 존재하는 이유다. **하지 마라:**
- 장소를 AI로 생성 — ADR-010. 실제 방문을 약속한 곳을 지어내면 약속의 허위 표시다
- 문구와 무관한 사진을 억지로 배치 — "It is stairs"라고 써놓고 계단이 없는 사진을 쓰면 그건 디자인 문제가 아니라 **신뢰 문제**다

**해야 할 것 (둘 중 하나):**
1. **문구를 가진 이미지에 맞춰 고친다.** 2단계로 돌아간다. 이게 정상 경로다
2. **`manifest.json`의 `wanted`에 촬영 요청을 등재하고** 그 카드를 보류한다. 요청에는 `for`(어느 카드)와 `subject`(무엇이 찍혀야 하는가)를 남긴다

### 라이선스 게이트

사진 위에 타입을 얹으면 그 카드는 **2차적 저작물**이다. `rights`에 따라 결과가 다르다:

| rights | 카드 발행 |
|--------|----------|
| `own`, `ai:*` | 자유 |
| `licensed:*` 중 public domain, CC BY | 크레딧 표기하고 발행 |
| **CC BY-SA** | **카드 자체를 동일 라이선스로 배포해야 한다.** 발행 전 사용자 확인 필수 |

CC BY-SA를 쓴 세트는 완성해도 좋지만 **발행 판정은 사용자에게 넘겨라.** 조용히 내보내지 마라.

## 4단계 — 생성

### 조판

`.lay-simple` 아키타입을 쓴다. 치수·클래스·유예된 규칙은 `brand.css`의 SIMPLE 블록과 `docs/UI_GUIDE.md` "현재 방향"에 있다. 여기서 되풀이하지 않는다 — **문서와 코드가 어긋나면 코드가 맞다.**

지켜야 할 것:
- `.lockup`, `.badge`, `.watermark`는 6장 전부 동일 위치. 이 고정 요소가 6장을 한 세트로 묶는다
- 색·크기를 인라인으로 새로 정의하지 마라. 위치 미세조정(`transform` 크롭, `max-width`)만 인라인 허용
- `<img>`에 `data-photo`(매니페스트 키)와 `data-slot`을 반드시 붙인다

### 렌더

```bash
node .claude/skills/cardnews-render/scripts/render-cards.mjs _workspace/03_cards.html output/cards
```

최초 1회: `cd .claude/skills/cardnews-render/scripts && npm i && npx playwright install chromium`
(**프로젝트 루트에 package.json을 만들지 마라** — 저장소 Stop 훅이 없는 npm 스크립트를 돌려 매 턴 실패한다.)

스크립트가 자동으로 잡는 것: 규격 · 프레임 이탈(클리핑 조상 예외) · 락업/페이저 충돌 · 한 줄 전제 요소의 줄바꿈 · **실제 렌더 픽셀 기준 대비** · 부기 라이선스 · 사진 출처와 슬롯.

**exit code가 0이 아니면 PNG가 나왔어도 완료가 아니다.** `NOTES` 블록은 exit code를 바꾸지 않는다 — 애매한 것만 거기로 간다.

### 컬러 액센트는 스크림을 더 요구한다

흰 글자는 휘도 1.0이라 얇은 스크림에서도 살지만, **오렌지는 0.35로 중간이라 볕 든 벽 위에서 그대로 사라진다.** 실측: 흰 글자 기준으로 잡아둔 스크림에서 액센트 구절이 1.18:1로 실패했다. 액센트를 새로 넣거나 사진을 바꿨으면 **대비 검사를 반드시 다시 돌려라.** 눈으로는 안 보인다.

### 육안 확인

렌더된 PNG를 **직접 Read해서** 본다. 스크립트는 기하와 픽셀만 보고 아래는 못 본다:
- 문구와 사진이 같은 것을 말하고 있는가 (3단계의 `image_intent` 대조)
- 6장을 나란히 놓았을 때 한 세트로 보이는가
- 크롭이 사진의 주제를 잘라먹지 않았는가

## 완료 보고

카드별 **역할 · 헤드라인 · 액센트 구절 · 사진 키 · rights** 표를 담아라. 다음 단계(`brand-qa`, `reels-producer`)가 이 표를 입력으로 쓴다. CC BY-SA가 하나라도 있으면 **발행 판정 대기**를 명시하라.

## 하지 마라

- **이미지 생성 AI로 카드 전체를 만들지 마라.** 텍스트를 정확히 못 그려서 오타가 박힌 채 발행된다 (ADR-001). 배경 이미지에만 쓴다
- **문구를 먼저 완성하고 사진을 나중에 찾지 마라.** 1단계에서 재고를 세는 이유다
- **브랜드 시스템에 없는 색을 추가하지 마라.** 필요하면 브랜드 시스템을 먼저 고친다
- 렌더 실패를 "PNG는 나왔으니 괜찮다"고 넘기지 마라

## 테스트 시나리오

**착수 조건 미충족**
> "자갈치시장으로 카드뉴스 만들어줘"
→ Step 0 초기 실행 판별 → 1단계: 랜딩 코스 O, 블로그 X(미발행), 사진 0장 → **착수 조건 미충족 보고.** 블로그 선행 또는 촬영이 필요함을 알리고 대안 주제를 제안한다. 없는 재고로 기획을 시작하지 않는다.

**정상 흐름**
> "감천마을로 카드뉴스"
→ 1단계 통과(코스 O, 블로그 O, 사진 5장) → 2단계 6칸 기획 + `fact_source` 기입 → 3단계 사진 매칭, 전부 CC BY-SA 확인 → 4단계 렌더 exit 0 → 육안 확인 → **완료 보고에 SA 발행 게이트 명시.**

**부분 재실행**
> "5번 카드 사진만 바꿔줘"
→ Step 0에서 부분 재실행 판별 → 3단계만 재수행 → `02_carousel.json`의 해당 `photo`만 교체 → 전체 재렌더(다른 카드의 HTML은 미수정) → **대비 검사 재확인** → 5번만 육안 확인.

**기획-이미지 충돌**
> 2단계에서 "계단으로 뒤덮인 골목" 문구를 짰는데 3단계에서 계단 사진이 없음
→ AI 생성 금지(장소 주장) → 문구를 보유 사진에 맞게 수정하거나, `wanted`에 촬영 요청 등재 후 해당 카드 보류 → **둘 중 무엇을 할지 사용자에게 묻는다.** 임의로 고르지 않는다.
