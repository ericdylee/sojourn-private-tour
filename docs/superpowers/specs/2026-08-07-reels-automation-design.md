# 설계: 릴스 영상 제작 자동화

**작성 2026-08-07 · 브랜치 `ericdylee/릴스영상자동화` · 상태: 검토 대기 (구현 미착수)**

## 무엇을 만드는가

카드뉴스 6장의 **HTML 원본에서 9:16 릴스를 다시 조판해 mp4로 뽑는 파이프라인**을 만든다.
소재가 준비되면 언제든 다시 돌릴 수 있는 제작 경로가 결승선이고, 특정 릴스 1편의 발행이
아니다.

크레딧을 쓰지 않는다. 카드 렌더와 같은 도구(Playwright + ffmpeg)만 쓴다.

## 전제가 바뀌었다 (2026-08-07)

착수 판단의 근거였던 두 가지가 이번 주에 움직였다.

## 구조

### 데이터 흐름

카드의 4단계 절차와 같은 형태다. 단계마다 파일이 남는 이유는 격식이 아니다 —
3단계에서 크롭이 안 맞는 게 드러나면 1단계로 돌아가야 하는데, 기획이 대화에만 있으면
전부 다시 해야 한다.

```
_workspace/02_carousel.json    카피·사진·팩트 출처 ─ 이미 있음. 릴스는 읽기만 한다
        │
        │  1단계  씬 구성 (에이전트 + 사람 승인)
        ▼
_workspace/04_reel_plan.json   씬 순서·길이·크롭·모션          [릴스 원장]
        │
        │  2단계  9:16 조판 + 크롭 확인 게이트
        ▼
_workspace/04_reel.html        1080×1920 · <section class="scene"> 4~5개 · 보존
        │
        │  3단계  씬별 프레임 캡처 → 씬 mp4 (해시 캐시)
        ▼
_workspace/.reel-cache/scene-NN.mp4   gitignore
        │
        │  4단계  concat + 규격 인코딩
        ▼
output/reels/reel.mp4          1080×1920 · 무음 트랙 포함 · H.264
output/reels/scene_plan.md     사람 승인용 (3단계 전에 먼저)
output/reels/caption.txt       인스타 캡션
```

**카피는 새로 쓰지 않는다.** `02_carousel.json`이 이미 팩트 출처까지 달아 검증한 문장이다.
릴스가 다시 쓰면 카드가 지킨 규율 밖으로 나간다.

**예외 하나: CTA 씬.** 카드 06의 원래 문구는 QA B1으로 교체됐다. CTA 씬은 교체된 현재
문구(`A private car and a day built around you.`)를 쓰고, 원장 `facts`가 덮는 범위를
넘지 않는지 1단계에서 다시 대조한다.

### 씬 단위 렌더 + 해시 캐시

전체를 하나의 타임라인으로 만들지 않는다. **씬마다 독립적으로 렌더하고 캐시한다.**

```
캐시 키 = sha256(
    씬 HTML 조각          그 씬만
  + brand.css + reel.css  조판 규칙 전체
  + assets/fonts/*        글자 모양
  + 그 씬이 쓰는 사진 파일
  + 씬 길이 · fps
  + 렌더러 버전 문자열
)
```

키가 같으면 씬 mp4를 통째로 건너뛴다.

**파일 구조는 카드와 같다.** `04_reel.html` 한 파일에 `<section class="scene">`가 4~5개 들어
있고, 렌더러가 한 번에 하나씩 격리해 찍는다. `render-cards.mjs`가 `<section class="card">`를
다루는 방식 그대로다. 씬을 파일로 쪼개면 공통 CSS와 순서가 어디에도 안 남는다.

**렌더러 버전 문자열**은 `render-reel.mjs` 상단 상수다. 모션 어휘나 인코딩 규격처럼
**같은 입력에서 다른 결과가 나오게 하는 변경**을 할 때 올린다. 올리면 전체 캐시가 무효화된다.

**CSS와 폰트를 키에 넣는 것이 핵심이다.** 씬 HTML만 해싱하면 `brand.css`를 고쳐도
낡은 씬이 재사용된다. 그러면 캐시가 거짓말을 하고, 이건 캐시가 없는 것보다 나쁘다.

이 구조를 고른 이유는 속도가 아니라 **부분 수정 가능성**이다. 이 프로젝트는 이미 같은
교훈을 얻었다 — 카드 05만 고치고 나머지 5장이 바이트 단위로 동일함을 sha256으로 확인한
것이 2026-08-06이다. 그리고 `reels-producer` 에이전트에는 **"재호출 시 씬 단위로만
교체한다"는 규정이 이미 있는데 지금은 구현이 없어 지킬 수가 없다.** 이 구조가 그 규정을
실행 가능하게 만든다.

### 결정론의 전제조건 — 폰트를 로컬로 내린다

`brand.css:5`가 Google Fonts를 `@import`한다.

```css
@import url('https://fonts.googleapis.com/css2?family=Anton&family=Inter:...&family=Montserrat:...');
```

**이 상태에서는 "같은 HTML → 같은 프레임"이 성립하지 않는다.**

- 네트워크가 실패하면 대체 글꼴로 렌더된다. `document.fonts.ready`는 그래도 resolve되므로
  **렌더러가 조용히 틀린 결과를 낸다.**
- Google이 Montserrat을 갱신하면 몇 달 뒤 재렌더 결과가 달라진다.

카드는 한 장씩 사람이 눈으로 보므로 견뎠지만, 프레임 수백 장에는 통하지 않는다.
**Montserrat 600/700/800 + Inter 필요 웨이트를 `assets/fonts/`에 woff2로 내리고
`@font-face`로 바꾼다.** 둘 다 SIL OFL이라 임베드가 자유롭고, 라이선스 파일을 같이 둔다.
현재 v4가 안 쓰는 Anton은 내리지 않는다.

부수 효과로 **카드 렌더도 같이 튼튼해진다.** 이건 릴스와 무관한 개선이 아니라, 이 설계의
중심 장치가 성립하기 위한 전제다.

### 프레임 캡처

씬마다 로컬 타임라인 `0..duration`을 갖는다. 캡처는 시간을 직접 감는다.

```js
await page.evaluate((t) => {
  document.getAnimations().forEach(a => { a.pause(); a.currentTime = t; });
}, tMs);
const buf = await page.screenshot();   // 디스크에 쓰지 않는다
ffmpegStdin.write(buf);                 // image2pipe로 바로 흘린다
```

실시간 녹화가 아니라 **시점을 지정해 꺼낸다.** 그래서 "13.4초 시점"을 정확히 재현할 수
있고, 검사에서 특정 프레임을 지목할 수 있다.

**프레임을 디스크에 쓰지 않는다.** 1080×1920 PNG는 장당 2~3MB라 450장이면 1GB가 넘는다.
Playwright의 스크린샷 버퍼를 ffmpeg stdin으로 바로 흘리면 임시 파일이 0이 된다.
디버깅용 `--dump-frames` 옵션만 남긴다.

> **이 설계에서 유일하게 안 해본 기술이다.** 구현 1단계에서 3초짜리 1씬으로 먼저 증명한다.
> `getAnimations()`가 CSS 애니메이션을 기대대로 잡지 못하면 대안은
> CDP `Animation.setPlaybackRate(0)` 또는 모든 모션을 단일 커스텀 속성 `--t`의 함수로
> 표현하는 방식이다. 계획 전체가 여기 얹히므로 먼저 세운다.

### 검사와 캡처는 페이지를 분리한다

**이걸 안 하면 글자 없는 영상이 나온다.**

기존 대비 검사는 페이지를 변조한다 — `__qa_noink` 스타일을 주입해 모든 글자를 투명하게
만들고, 요소에 `data-qa-ink` 속성을 붙인 뒤, 그 배경 스크린샷과 대조한다. 캡처와 같은
페이지에서 돌리면 그 부작용이 그대로 영상에 굽힌다.

**검사 전용 페이지를 따로 연다.** 캡처 페이지는 아무도 건드리지 않는다. 검사가 자기
뒷정리를 하도록 만드는 것보다 확실하고, 실패 모드가 존재하지 않게 된다.

## 씬 길이 — 균등분할하지 않는다

세 단어짜리 헤드라인과 아홉 단어짜리 헤드라인에 같은 시간을 주면 둘 다 틀린다.

```
길이 = 0.4(등장) + 단어수 × 0.35 + 0.6(여유)
       하한 1.8초 · 상한 4.5초
```

기계가 계산하고, `04_reel_plan.json`에서 사람이 씬별로 덮어쓸 수 있다.

**씬은 4~5개다. 카드 6장을 전부 넣지 않는다.** 6장이면 씬당 3초에 헤드라인 2줄인데
세로 화면에서 빡빡하다. 어느 카드를 뺄지는 기획 판단이라 1단계에서 정하고 사람이 승인한다.

**훅 씬이 카드 01이어야 한다는 규정은 푼다.** 현행 스킬은 "훅 카피는 카드 01의 Display를
그대로" 쓰라고 하는데, 카드 01은 표지다. 표지는 제목이지 훅이 아니다. 훅 카피는 원장이
검증한 문장 중에서 고른다 — 출처가 같으므로 팩트 규율은 그대로다.

## 검사

기존 4종을 9:16에 얹고 릴스 전용 3종을 더한다. 판정 등급은 렌더러의 기존 규율을 따른다 —
확실히 깨진 것만 ISSUE(exit 비0), 다툼의 여지가 있으면 NOTE.

| 검사 | 등급 | 근거 |
|---|---|---|
| 프레임 1080×1920 | ISSUE | 규격 |
| 오버플로우 | ISSUE | 기존 재사용 |
| 사진 원장 대조 · AI 금지 | ISSUE | 기존 재사용 |
| **대비 — 씬당 3프레임 최악값** | ISSUE / NOTE | 아래 참조 |
| **세이프에어리어** | ISSUE | 상단 200px / 하단 400px에 글자·CTA가 들어가면 인스타 UI가 덮는다 |
| **동시 표시 단어 수 6개 상한** | ISSUE | 세로 화면에서 못 읽는다. 스킬에 이미 있는 규정 |
| 길이 15~25초 | NOTE | 스킬 규정 |

**대비를 씬당 3프레임(시작·중간·끝)에서 재고 최악값으로 판정한다.** ken-burns가 사진을
확대하는 동안 글자 뒤 배경이 계속 바뀌므로 한 프레임 측정은 틀린 측정이다. 중간에서
5:1이어도 마지막 프레임에서 1.8:1일 수 있다. QA가 카드에서 잡은 M1(URL이 밝은 지붕 위에서
1.75:1)이 정확히 이 종류이고, **정지 이미지에서도 놓쳤다.** 움직이면 더 놓친다.

**폐기한 검사 하나를 기록한다.** 초안에는 "훅 0~3초의 인접 프레임 픽셀 차가 0이면 정지
화면으로 시작한 것"이라는 검사가 있었다. ken-burns가 모든 씬에 걸려 있으므로 픽셀 차는
절대 0이 아니다 — **항상 통과하는 검사**였다. 렌더러 자신의 설계 원칙이 "사람이 무시하는
검사는 없느니만 못하다"인데 이건 기계가 무시하는 검사다. 단어 수 상한으로 대체했다.

## 발행 사고를 기계가 막는다

파이프라인은 QA가 HOLD여도 돌아간다. 그래서 사람이 그 영상을 실수로 올릴 수 있다.

`render-reel.mjs`가 두 가지를 직접 읽는다.

1. `output/qa_report.md`의 최신 판정
2. 씬이 쓰는 사진의 매니페스트 `rights` — 상업 이용이나 2차저작 재배포에 조건이 붙는가

**둘 중 하나라도 통과가 아니면:**

- 파일명이 `reel.mp4`가 아니라 **`reel_INTERNAL.mp4`**
- **전 프레임에 `INTERNAL DRAFT — NOT FOR PUBLICATION` 배너를 굽는다**
- 어느 조건이 걸렸는지 콘솔에 출력한다

**판정은 fail-closed다.** PASS를 적극적으로 증명하지 못하면 INTERNAL이다. `qa_report.md`는
마크다운이라 파싱이 깨질 수 있는데, 깨졌을 때 안전한 쪽은 배너가 붙는 쪽이다.

"내부 시안까지만 허용"이 사람의 기억이 아니라 **파일 자체의 성질**이 된다.

## 저작자 표시

현재 사진은 CC BY 4.0(5장)과 CC0(1장)이다. **CC BY는 저작자 표시가 의무다.**

카드는 `.photo-credit`을 하단에 둔다. 릴스에서는 그 자리를 인스타 UI가 덮으므로
**하단 400px 구역 바로 위(y ≈ 1450~1500)에 크레딧을 둔다.** 캡션 텍스트에만 적는 것으로
갈음하지 않는다 — 캡션은 접히고, 영상은 재배포되면 캡션과 분리된다.

씬마다 사진이 다르므로 **크레딧도 씬마다 바뀐다.** 매니페스트 `rights`에서 렌더 시점에
읽어 넣는다. 손으로 적지 않는다.

카드에서 이미 관측된 문제 하나를 되풀이하지 않는다: QA m2가 지적한 대로 카드의
`.photo-credit`은 **크롭 가드 안에 있다** — 라이선스 의무를 충족시키는 유일한 요소가
시스템이 스스로 "잘릴 수 있다"고 선언한 영역에 있다. 릴스에서는 처음부터 안전 영역에 둔다.

## 코드가 사는 곳

`render-cards.mjs`는 613줄 단일 스크립트라 함수를 밖에서 못 쓴다. 릴스가 필요로 하는 두
검사(사진 원장 대조, 대비 실측)가 그 안에 묻혀 있다. **딱 그 둘만 모듈로 빼고 나머지는
안 건드린다.**

```
.claude/skills/cardnews-render/scripts/
  lib/photos.mjs      사진 원장 · AI 금지 · 라이선스     ← render-cards.mjs에서 이동
  lib/contrast.mjs    글자/배경 대비 실측                ← 이동
  render-cards.mjs    1080×1080 (위 둘을 import — 동작 불변)
  render-reel.mjs     1080×1920 (신규)
  package.json        playwright — 그대로 공유
assets/fonts/         Montserrat · Inter woff2 + OFL 라이선스 (신규)
```

**디렉터리를 하나로 둔다.** `CLAUDE.md`의 CRITICAL 규칙이 렌더 의존성 격리 위치로 이 경로를
지목하고 있고, 두 번째 `package.json`을 만들면 playwright 버전이 두 군데서 갈린다. 대가는
이름이 "cardnews"인데 릴스도 산다는 것 — 파일 헤더에 사유를 적는다.

**모듈 경계는 `checkContrast({ page, root, config }) → findings[]` 형태로 정한다.**
대비 검사는 `page.evaluate` 안에서 도는 다단계 루틴이라 단순한 함수 이동이 아니다.
페이지를 받아 자기가 알아서 evaluate하는 경계로 잡으면 클로저 문제를 우회한다.

**이 이동의 완료 조건은 카드 6장 재렌더 후 sha256 6/6 동일이다.** 릴스 기능과 섞지 않고
독립 단계로 끊는다.

## 검증 — 결함 재현 테스트

ADR-014가 세운 이 프로젝트의 방식이다. 새 검사마다 **일부러 깨진 픽스처를 만들어 반드시
실패하는 것을 확인한다.** 검사가 실제로 작동하는지는 그 방법으로만 알 수 있다.

| # | 픽스처 | 기대 |
|---|---|---|
| 1 | 하단 380px 지점에 CTA를 놓은 씬 | 세이프에어리어 ISSUE |
| 2 | 헤드라인 7단어인 씬 | 단어 수 ISSUE |
| 3 | **시작 프레임은 멀쩡하고 끝 프레임에서 대비가 무너지는 씬** | 대비 ISSUE — 1프레임 검사로는 못 잡는다는 증명 |
| 4 | 씬 3만 수정 후 재렌더 | 나머지 씬 mp4 sha256 동일 |
| 5 | QA HOLD 상태에서 렌더 | `reel_INTERNAL.mp4` + 배너 |
| 6 | 폰트 파일을 치운 상태로 렌더 | 조용히 성공하지 않는다 |

6번이 특히 중요하다. 폰트 로컬화의 목적이 "조용히 틀리지 않는 것"이므로, 그 실패가 실제로
시끄러운지 확인해야 한다.

## 출력 규격

H.264 High · `yuv420p` · 30fps · ~12Mbps · **무음 AAC 128k 트랙 포함.**

무음을 "오디오 트랙 없음"으로 구현하지 않는다. **인스타그램은 오디오 트랙이 없는 mp4를
업로드에서 거부하는 경우가 있다.** 무음 트랙을 넣는다.

`reel.mp4`는 git에 커밋한다(`output/cards/*.png`가 이미 커밋돼 있어 일관된다).
`_workspace/.reel-cache/`는 gitignore.

## 스킬 · 에이전트 드리프트 제거

현재 상태로 릴스 에이전트를 돌리면 **만족될 수 없는 조건 앞에서 멈춘다.**

| 파일 | 고칠 것 |

**부기 관련 서술은 통째로 삭제하고 한 줄 포인터만 남긴다** — `부기 캐릭터는 사용 보류다

규정 원문은 이미 그 파일에 전부 있으므로 잃는 것이 없고, 쓰지 않을 캐릭터의 규정을 두 군데서
관리하지 않는다.

**게이트는 에이전트가 연다. 스크립트는 검사하고 렌더할 뿐이다.** `scene_plan.md` 승인과
크롭 확인은 `mcp__gate__ask_approval`로 에이전트가 요청한다. 스크립트가 사람을 부르지 않는다.

## 고려했다 버린 대안

**① ffmpeg 단독 (zoompan 켄번스).** 씬당 PNG 2장(사진층·글자층)만 뽑고 모션 전부를 ffmpeg
필터로 처리한다. 50배 빠르고 `getAnimations()` 리스크가 없다. 버린 이유: 레이어를 분리하려면
`brand.css`를 사진층/글자층으로 쪼개야 하고, `zoompan`은 정수 단위로 동작해 지터가 알려진
문제라 회피 기법이 따로 필요하며, 모션 어휘가 필터로 고정된다. 속도 부담은 씬 캐시가 흡수한다.

**② Higgsfield image-to-video.** 감천 실사진을 넣으면 AI가 **실재하는 장소의 없던 프레임을
그린다.** 골목이 이어지고 사람이 움직이는데 그건 우리가 찍지 않은 감천이다. 카드에서 금지한
것(ADR-010)과 같은 종류의 주장이고, 매번 결과가 달라 검사가 성립하지 않는다. 크레딧 소모는
그다음 문제다.

**③ 카드 PNG를 1080×1920 중앙에 배치 (현행 스킬 규정).** 검수 통과본을 한 픽셀도 안 건드리는
장점이 있다. 버린 이유: 그 규정은 카드가 타이포 중심이던 v1 시절에 쓰였다. v4는 사진이 배경
전체라 위아래 색 띠로 가두면 화면 절반이 빈다.

## 미해결 — 이 설계가 답하지 않는 것

**이 포맷의 천장은 동영상 소재가 없다는 데서 온다.** 사진에 느린 확대를 거는 것은 정직한
차선책이지 그 이상이 아니다.

`docs/SHOTLIST.md`는 지금 **정지 사진만** 나열한다. 우선순위 A를 찍으러 갈 때 같은 자리에서
**5~10초짜리 클립을 같이 찍으면 비용이 거의 들지 않으면서 이 포맷의 천장이 영구히 올라간다.**
특히 A5(전용 차량 실내)는 움직임이 있어야 상품 차별점이 전달된다 — 정지 사진으로는 "차가
있다"까지만 말할 수 있다.

SHOTLIST에 영상 항목을 추가하는 것을 구현 계획에 포함한다. 촬영 자체는 사람 몫이다.
