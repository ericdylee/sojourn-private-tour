# 설계: Sojourn 콘텐츠 자동화 — 데스크톱 앱

**작성 2026-08-06 · 상태: 검토 대기 (구현 미착수)**

## 무엇을 만드는가

지금은 터미널에서 `cd web && npm start`를 쳐야 콘솔이 뜬다. 이걸 **바탕화면 아이콘을
누르면 열리는 프로그램**으로 만든다. 사용자는 두 명 — 맥 1, 윈도우 1.

서버에 올리지 않는다. 각자 자기 컴퓨터에서 돌리고, 두 컴퓨터 사이는 **GitHub가 원본**
역할을 한다.

```
[맥]     아이콘 → 콘솔 → 실행 → 결과 ─┐
                                       ├─ GitHub (원본)
[윈도우] 아이콘 → 콘솔 → 실행 → 결과 ─┘
```

## 왜 서버가 아닌가

원래 요청은 "Vercel에 배포"였다. 세 가지 이유로 접었다.

1. **성격이 안 맞는다.** Vercel은 요청을 받아 응답하고 끝나는 곳이다. 이 콘솔은 몇 분씩
   돌면서 파일을 쌓는다. 저장 공간이 요청마다 사라지므로 만든 카드가 남지 않는다.
2. **위험이 다르다.** 콘솔은 에이전트의 도구 사용을 **전부 자동 승인**한다
   (`web/lib/runner.mjs:283`). 안전장치는 `scripts/guard.py` 하나이고 막는 명령이 네 개뿐
   (`rm -rf`, `git push --force`, `git reset --hard`, `DROP TABLE`)이다. 공개 주소가 생기면
   주소를 찾은 사람이 그 서버에서 아무 명령이나 실행할 수 있다.
3. **로컬이면 인증 문제가 사라진다.** 각자 자기 Claude 계정으로 로그인한다. 공유 API 키도,
   서버 자격증명도, 비용 합산도 없다.

## 확인된 사실 (조사 완료)

| 항목 | 결과 |
|---|---|
| 윈도우 지원 | **된다.** SDK 매니페스트에 `win32-x64` / `win32-arm64` 항목이 있고 `claude.exe`를 가리킨다 |
| Claude Code 별도 설치 | **불필요.** `optionalDependencies`가 플랫폼별 바이너리를 담고 있고, `package-lock.json`에 8개 플랫폼이 전부 들어 있어 `npm ci`가 알맞은 것을 받는다 |
| 렌더러 플랫폼 의존성 | **없다.** `render-cards.mjs`에 `__dirname`·`/tmp`·`spawn`·플랫폼 분기가 없다 |
| 개념 이미지(gpt-image-2) | 스킬이 호출하지 않는다. 문서(PRD·ADR)에만 언급된 **사람의 수동 단계**라 자동화 의존성이 아니다 |
| 사전 설치 필요 | **Node.js 18+ 하나뿐** |

## 구성 요소

### 1. 런처 (`web/launch.mjs`)

아이콘을 누르면 실행되는 진입점. 순서:

1. **중복 실행 방지** — 포트가 이미 열려 있으면 서버를 새로 띄우지 않고 브라우저만 연다.
2. **서버 기동** → 포트가 열릴 때까지 대기 → **기본 브라우저 열기**.
3. 화면이 **셋업 점검 결과**를 먼저 보여준다. 통과 못 하면 실행 버튼이 잠긴다.
4. **GitHub에서 최신 받아오기.**

**종료**: 브라우저 탭을 닫아도 서버는 남는다. 화면에 종료 버튼을 두고, 붙어 있는 화면이
없는 상태가 일정 시간 지나면 스스로 꺼진다. 다만 **실행 중에는 자동 종료하지 않는다** —
아래 §6 참조.

### 2. 아이콘 래퍼

| OS | 형태 |
|---|---|
| macOS | `Sojourn 콘텐츠 자동화.app` — 최소 번들. `Contents/MacOS/`의 셸 스크립트가 `node launch.mjs`를 부른다. 터미널 창이 뜨지 않는다 |
| Windows | 실행 파일 + 바탕화면 바로가기(아이콘 지정·창 숨김). 검은 콘솔 창이 뜨지 않게 한다 |

### 3. 셋업 점검 화면

팀원이 터미널을 쓰지 않아도 되도록, **뭐가 없는지 화면이 말하고 버튼으로 고친다.**

| 확인 항목 | 없을 때 |
|---|---|
| Node.js 18+ | 설치 링크 안내 (유일하게 사람이 직접) |
| `web/node_modules` | 버튼 → `npm ci` |
| 렌더 의존성 + Chromium | 버튼 → `npm i && npx playwright install chromium` |
| Claude 로그인 | 로그인 방법 안내. 각자 자기 계정, 한 번만 |
| Git · GitHub 접근 권한 | 안내 |
| **안전장치 동작** | §4 참조. 실패 시 실행 잠금 |

### 4. 안전장치 크로스플랫폼화 — `guard.py` → `guard.mjs`

현재 훅은 `python3 "$CLAUDE_PROJECT_DIR/scripts/guard.py"`다. 파이썬 의존과 셸 변수 확장이
윈도우에서 문제가 된다. **Node로 옮긴다** — Node는 이미 필수라 새 의존성이 없다.
차단 목록과 종료 코드 규약(exit 2 = 차단)은 그대로 두고, 파이썬 판과 결과가 같은지
확인하는 회귀 테스트를 붙인다.

**이 설계에서 가장 조심할 지점이다.** 훅은 실행에 실패해도 에러를 내지 않고 **조용히
통과**한다. 안전장치가 없는 줄 모르고 쓰게 된다.

→ 셋업 점검에 **일부러 위험한 명령을 넣어 실제로 차단되는지 확인하는 자체 테스트**를
넣는다. 통과 못 하면 실행 버튼을 잠근다.

**미검증**: 윈도우에서 훅의 경로 표기(`$CLAUDE_PROJECT_DIR`)가 확장되는지는 팀원 컴퓨터에서
실측해야 한다. 상대 경로(`node scripts/guard.mjs`) 대안을 함께 준비한다.

### 5. GitHub 동기화

- **실행 전**: `git pull --ff-only`. 두 컴퓨터의 작업이 **갈라져 있으면 실행을 막고** 알린다.
  카드 PNG는 자동 병합이 불가능해서, 갈라진 채로 돌리면 한쪽 작업이 사라진다.
- **실행 후**: "결과를 팀에 올릴까요?" 승인 카드 → 승인 시 커밋·푸시. **자동으로 올리지
  않는다** — 잘못 나온 결과가 올라가면 안 된다. 기존 게이트 구조를 그대로 쓴다.
- **팩트 원장(`_workspace/01_brief.json`)만 예외**: 편집 즉시 올린다. 원장이 두 벌로
  갈라지는 것이 가장 나쁘다.
- **동시 실행**: 완전히 막을 수 없다. 2명이라 현실적으로 드물고, 실행 전 검사가 대부분
  잡는다. 화면에 "마지막으로 누가 언제 돌렸는지"를 표시해 더 줄인다.

### 6. 재접속 복구 — **2026-08-06 첫 실사용에서 발견**

콘솔을 실제로 돌려보다 결함 두 건이 나왔다. 둘 다 앱으로 포장하면 **더 자주** 터진다.

**① 승인 카드의 버튼이 화면 밖으로 밀린다.**
에이전트가 승인 근거를 길게 쓰면(길게 쓰는 것이 옳다) 승인/반려 버튼이 스크롤 위로
사라져 버튼의 존재조차 보이지 않는다. 실제로 이 때문에 한 번 막혔다.
→ **버튼을 카드 안에 고정(sticky)하거나 근거 위로 올린다.**

**② 탭을 닫으면 진행 중인 실행과 화면이 끊긴다.**
탭이 닫혔을 때 서버는 게이트를 열어둔 채 정상 대기하고 있었다. 그런데 새 탭으로 다시
들어가 누른 승인이 먹지 않았고, 결국 `POST /api/gates/:id`로 직접 응답해 풀었다.
→ **재접속 시 열린 게이트가 화면에 복구되어야 한다.** 앱은 창을 닫는 일이 브라우저 탭보다
흔하므로 이건 선택이 아니다.
→ 연계: 실행 중에는 자동 종료를 걸지 않는다. 화면이 없다고 꺼지면 대기 중인 게이트가
사라진다.

**게이트는 오래 열려 있는다 — 이건 결함이 아니라 정상이다.**
같은 날 QA 실행에서 게이트 하나가 **47분** 열려 있었다(사람이 답할 때까지). 실제 에이전트
작업 시간은 10분 남짓이었고 나머지는 전부 대기였다. 설계상 옳은 동작이지만 두 가지를
요구한다: (a) 자동 종료 타이머는 **게이트 대기를 살아 있는 상태로 취급**해야 한다,
(b) 화면에 "무엇을 기다리는 중인지"가 보여야 한다 — 그렇지 않으면 멈춘 것처럼 보인다.

## 데이터 흐름

```
아이콘 클릭
  → 런처: 중복 확인 → 서버 기동 → 브라우저 열기
  → 셋업 점검 (안전장치 자체 테스트 포함) — 실패 시 실행 잠금
  → git pull --ff-only — 갈라졌으면 실행 차단
  → 에이전트 선택 → 지시 → 실행
  → (승인 게이트: 화면에 카드. 재접속해도 복구됨)
  → 결과 확인 → "팀에 올릴까요?" 승인 → 커밋·푸시
```

## 오류 처리

| 상황 | 처리 |
|---|---|
| 포트가 이미 사용 중 | 우리 서버면 브라우저만 열고, 남의 프로세스면 화면에 알리고 다른 포트 제안 |
| 서버가 죽음 | 런처가 감지해 화면에 알린다. 조용히 실패하지 않는다 |
| 브라우저를 못 열음 | 주소를 화면(터미널 출력)에 남긴다 |
| git이 갈라짐 | 실행 차단 + 무엇이 갈라졌는지 파일 목록 표시 |
| 푸시 실패 (인증·권한) | 작업물은 로컬에 남기고 안내. 조용히 버리지 않는다 |
| 안전장치 자체 테스트 실패 | **실행 버튼 잠금.** 우회 수단을 두지 않는다 |

## 테스트

- **런처**: 포트 선점 / 서버 조기 종료 / 브라우저 실행 실패
- **`guard.mjs`**: 파이썬 판과 동일한 차단·통과 결과 (회귀), 정상 명령 오탐 없음
- **안전장치 자체 테스트**: 훅이 없거나 죽었을 때 실행이 잠기는가
- **동기화**: 갈라진 상태에서 실행이 막히는가, 푸시 실패 시 안내가 뜨는가
- **재접속 복구**: 게이트가 열린 상태에서 창을 닫고 다시 열면 카드가 살아나는가

## 범위 밖

- 서버 배포, 로그인 화면, 다중 사용자 권한 — 로컬 앱이므로 불필요
- 자동 발행 (ADR-009)
- 3명 이상 동시 사용 — 지금 설계는 2인 기준이다

## 알려진 한계

**윈도우는 이 저장소에서 검증할 수 없다.** 코드는 양쪽 다 되게 쓰지만, 실제 동작은 팀원
컴퓨터의 첫 실행에서 확인된다. 그래서 셋업 점검 화면을 **"왜 안 되는지 스스로 말하게"**
만드는 데 비중을 둔다 — 첫 시도에서 걸려도 원인이 화면에 뜨도록.
