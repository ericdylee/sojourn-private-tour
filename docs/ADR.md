# Architecture Decision Records

## 철학

**발행은 되돌릴 수 없다.** 인스타 카드뉴스는 링크를 못 고치고, SNS는 수정해도 캡처가 남고, 틀린 가격은 환불·분쟁 사유가 된다. 그래서 이 프로젝트의 모든 결정은 "빠르게 많이 만들기"보다 **"틀린 것이 나가지 않게 하기"** 를 우선한다.

두 번째 원칙: **1인 운영을 전제한다.** 사람이 매번 판단해야 하는 지점은 문서와 코드로 고정한다. 판단을 줄이는 결정이 좋은 결정이다.

---

### ADR-001: 카드뉴스를 HTML/CSS + Playwright 스크린샷으로 만든다
**결정**: 1080×1080 HTML을 조판하고 Playwright로 PNG를 캡처한다. 이미지 생성 AI나 Canva 템플릿을 쓰지 않는다.
**이유**: 이 브랜드의 디자인 문법은 초대형 타이포가 주인공이다. 이미지 생성 모델은 텍스트를 정확히 못 그려서 오타가 박힌 채 발행된다. Canva는 템플릿 제약으로 블리드 타이포·콜라주를 재현하기 어렵다. HTML은 픽셀 단위 제어가 되고, 문구만 바꿔 무한 재생산할 수 있으며, **렌더 단계에서 기계 검증을 붙일 수 있다.**
**트레이드오프**: 비개발자가 손으로 수정하기 어렵다. 웹폰트 로딩 실패 시 조용히 다른 레이아웃이 나올 수 있어 렌더러가 폰트 로딩을 명시적으로 기다린다.

### ADR-002: 콘텐츠 언어는 영어 단독
**결정**: 카드뉴스·블로그·SNS 전부 영어. 한국어판을 만들지 않는다.
**이유**: sojournkorea.net이 전면 영문이다. 한국어 콘텐츠를 보고 영문 랜딩에 도착하면 경험이 끊기고 이탈한다. 타겟도 부산 방문 외국인·주재원이다.
**트레이드오프**: Threads의 한국 유저 트래픽과 네이버 검색 유입을 포기한다. 국내 지인·기업 HR을 통한 소개 경로도 약해진다.

### ADR-003: 카드 카피와 레이아웃을 한 에이전트가 담당한다
**결정**: `card-producer`가 문구 작성부터 HTML 조판, 렌더까지 일괄 처리한다. 카피라이터와 디자이너를 분리하지 않는다.
**이유**: 레퍼런스 스타일에서는 **헤드라인 길이가 곧 레이아웃**이다. 카피를 따로 받아 얹으면 "부산 프라이빗 투어로 하루를 완성하세요" 같은 문장이 와서 210px로 못 키우고, 크기를 줄이는 순간 레퍼런스 룩이 죽는다. 길면 줄이는 게 아니라 **단어를 바꿔야** 하는데 그 판단은 레이아웃을 아는 사람만 할 수 있다.
**트레이드오프**: 이 에이전트의 작업 범위가 넓어 실패 시 영향이 크다. 블로그·SNS와의 문구 중복은 팀 내부 메시지 교환으로 따로 막는다.

### ADR-004: 부기를 AI로 생성·변형하지 않는다
**결정**: Higgsfield 등으로 부기의 새 포즈·표정·의상을 만들지 않는다. 배경 제거와 업스케일만 허용한다. 포즈가 필요하면 부산시 공식 응용동작 카탈로그에서 고른다.
**이유**: 부기 라이선스는 공공누리 **제4유형** — 출처표시 + 상업적 이용 금지 + **변형 등 2차적 저작물 작성 금지**다. AI 생성은 2차적 저작물 작성에 해당한다. "결과가 원본과 비슷한지 대조하면 된다"는 완화책이 아니다 — **만드는 행위 자체가 승인 대상**이다. 다행히 부산시가 여행·관광 응용동작(비행기, 캐리어, 갈맷길, 서핑, 관광안내, 가족 사진)을 이미 제공한다.
**트레이드오프**: 연출 자유도가 줄고, 카탈로그에 없는 상황은 표현할 수 없다. 초기 검토에서 AI 포즈 변형을 권했다가 가이드북 확인 후 철회한 결정이다.

### ADR-005: 브리프의 팩트 원장이 모든 사실 주장의 단일 출처다
**결정**: `_workspace/01_brief.json`의 `facts` 배열에 없는 가격·소요시간·운영시간·후기를 어떤 산출물에도 쓰지 않는다. 확인 못 한 항목은 `source: "UNVERIFIED"`로 남기되 사용은 금지한다.
**이유**: 카드·블로그·SNS·릴스가 각자 사실을 조달하면 채널 간 값이 갈라진다. 카드가 "4 hours", 블로그가 "5 hours"라고 말하는 순간 둘 다 신뢰를 잃는다. 투어는 실제 이행 약속이라 틀린 숫자는 환불·분쟁 사유다.
**트레이드오프**: 원장에 없는 정보 때문에 카피가 밋밋해질 때가 있다. 실제로 랜딩에 가격이 없어 가격 소구를 통째로 포기했고, 검증된 후기가 없어 후기 카드를 팩트 카드로 대체했다.

### ADR-006: 검증을 CSS·스크립트·에이전트 3층으로 나눈다
**결정**: 규칙을 CSS 클래스로 고정하고, 기하학적 위반은 렌더 스크립트가 exit code로 막고, 판단이 필요한 것만 QA 에이전트가 본다.
**이유**: 사람도 LLM도 "카드 6장이 정확히 1080×1080인가", "글자가 프레임 밖으로 나갔는가"를 눈으로 반복 확인하는 데 약하다. 반대로 "저작권 표기가 캐릭터에 가려 안 읽히는가"는 기하학적으로 통과하므로 기계가 못 잡는다. 각 층이 잘하는 것만 맡긴다.
**트레이드오프**: 렌더 스크립트가 복잡해졌고, 스크립트 자체의 버그(회전 변환을 왜곡으로 오판하는 거짓 양성 등)를 별도로 검증해야 했다.

### ADR-007: 브랜드 규칙을 `sojourn-brand-system` 한 곳에만 정의한다
**결정**: 컬러 토큰·타입 스케일·부기 규칙·톤·금지 표현을 스킬 하나에 모으고, 나머지 5개 스킬은 여기서 정의한 값만 참조한다. 값이 필요하면 각자 정하지 말고 이 파일을 고친다.
**이유**: 6장 카드가 서로 다른 브랜드처럼 보이는 가장 흔한 원인은 규칙이 여러 곳에 흩어져 미묘하게 달라지는 것이다.
**트레이드오프**: 이 파일이 커지면 모든 에이전트의 컨텍스트를 먹는다. 부기 상세 규정은 `references/boogie-usage.md`로 분리해 필요할 때만 읽게 했다.

### ADR-008: 프로젝트 루트에 `package.json`을 두지 않는다
**결정**: Playwright 의존성을 `.claude/skills/cardnews-render/scripts/`에 격리한다.
**이유**: `.claude/settings.json`의 Stop 훅이 `[ -f package.json ]`로 분기해 `npm run lint && build && test`를 실행한다. 루트에 package.json이 생기면 존재하지 않는 스크립트를 매 턴 실행해 항상 실패한다.
**트레이드오프**: 렌더 실행 시 경로가 길어진다. 훅을 고치는 선택지도 있었으나, 하네스 표준 설정을 건드리지 않는 쪽을 택했다.

### ADR-010: 장소 이미지는 AI로 생성하지 않는다
**결정**: 감천문화마을·자갈치·해동 용궁사·광안대교 등 **실제 방문을 약속한 장소**의 이미지는 실사진 또는 라이선스 스톡만 쓴다. AI 생성은 특정 장소가 아닌 개념·소품·질감(`slot: "concept"`)에만 허용한다. `assets/photos/manifest.json`에 등재되지 않은 이미지는 렌더러가 차단한다.
**이유**: ADR-005에서 확인 안 된 가격을 금지한 것과 같은 종류의 문제다. 투어는 실제 이행 약속이고, 실물과 다른 장소 이미지는 스타일 선택이 아니라 **약속의 허위 표시**다. 여기에 세 가지가 더 붙는다 — 용궁사 지붕선이나 광안대교 주탑처럼 형태가 특정된 구조물을 생성 모델이 반드시 뭉개고, 인스타·메타가 생성 이미지에 AI 라벨을 붙이며, "현지에 사는 사람의 목소리"라는 톤과 정면으로 충돌한다.
**트레이드오프**: 실사진을 확보할 때까지 장소 카드를 채울 수 없다. 대신 운영자가 직접 찍은 사진은 경쟁 OTA 상품 페이지가 가질 수 없는 자산이 되므로, 제약이 곧 차별점으로 바뀐다.

### ADR-011: 이미지 생성은 이미 연결된 Higgsfield로 하고 OpenAI를 추가하지 않는다
**결정**: `gpt-image-2` API를 붙이지 않는다. 생성·업스케일·아웃페인팅·배경제거를 Higgsfield MCP로 처리한다.
**이유**: 기능이 상당 부분 겹치는데 API 키·과금·호출 코드·유지보수가 늘어난다. `gpt-image-2`의 차별점은 **이미지 안 텍스트 렌더링과 편집 지시 이행력**인데, 우리는 텍스트를 HTML로 넣기로 이미 정했다(ADR-001). 가장 큰 장점이 우리에게는 쓰이지 않는 장점이다.
**트레이드오프**: 실사진 마스크 편집·합성 품질에서 손해를 볼 수 있다. 실제로 부족한 지점이 나오면 그때 추가한다 — 비용은 캠페인당 4달러 안쪽이라 재검토 비용이 낮다.

### ADR-009: 발행 자동화를 MVP에서 제외한다
**결정**: 파일 산출까지만 하고 채널 발행은 사람이 한다. `publish-ops` 에이전트를 만들지 않았다.
**이유**: 각 채널 API 토큰과 비즈니스 계정 연동이 선행되어야 하고, 무엇보다 **승인 없이 나가는 발행 사고**를 막는 장치를 따로 설계해야 한다. 부기 라이선스도 미승인 상태라 자동 발행은 위험이 이득보다 크다.
**트레이드오프**: 매 캠페인마다 수동 업로드 시간이 든다. 라이선스 승인과 첫 캠페인 성과 확인 후 재검토한다.
