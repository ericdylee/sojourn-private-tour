# 캠페인 콘솔

부산 프라이빗 투어 에이전트를 브라우저에서 실행하는 **로컬 전용** 콘솔.

```bash
cd web
npm install          # 최초 1회
npm start            # → http://127.0.0.1:4173
```

## 한 번에 에이전트 한 명

전체 캠페인을 한 번에 돌리는 버튼은 **의도적으로 없다.** 원장을 다시 쓰고
네 채널을 무인으로 갈아엎는 파이프라인은 틀렸을 때 가장 비싸고, 중간에
멈추기도 어렵다. 원장을 확인하고 → 카드 제작자를 돌리고 → QA를 돌리는 식으로
사람이 한 단계씩 판단한다.

`busan-campaign` 오케스트레이터는 하네스에 그대로 살아 있다. 지시문에서
쓰라고 하면 쓴다 — 다만 버튼이 아닐 뿐이다.

각 에이전트에는 **프리셋**이 붙어 있다 (`lib/prompts.mjs`). 지시함을 채워주는
출발점일 뿐 고정 명령이 아니므로, 누른 뒤 고쳐서 쓰면 된다.

## 팩트 원장은 사람이 소유한다

`_workspace/01_brief.json` 을 쓰는 에이전트는 없다. 2026-08-05에
`campaign-strategist` 를 제거하고 원장 소유권을 사람에게 넘겼다.

이유는 사고 기록에 있다 — 원장이 랜딩에 없는 운영시간을 주장했고(QA B2)
그게 카드 03에 그대로 나갔다. 원장이 틀리면 네 채널이 동시에 틀린다.
한 사람이 책임지는 편이 낫다.

에이전트는 원장을 **읽고, 대조하고, 지적**한다. 고치지는 않는다.
브리프 화면에서 새로 만들거나 편집하며, 새 원장은 QA가 쌓아온 표준 금지
규칙(요금·소요시간·후기 UNVERIFIED 3건 + 금지 표현 5건)을 갖고 시작한다.

## 설계의 핵심: 하네스를 복제하지 않는다

콘솔은 캠페인 규칙을 하나도 갖고 있지 않다. Claude Agent SDK를
`cwd: <레포 루트>` + `settingSources: ['project']` 로 띄우면
`.claude/agents/` 5인, `.claude/skills/` 8개, `.claude/settings.json` 의
`guard.py` PreToolUse 훅까지 **터미널 세션과 동일하게** 로드된다.
콘솔이 하는 일은 트리거 문장을 던지고 이벤트 스트림을 화면으로 옮기는 것뿐이다.

스킬이나 에이전트를 고치면 콘솔도 같이 바뀐다. 규칙이 두 군데 살지 않는다.

라이브 화면 상단의 **하네스 스트립**이 이걸 매 실행마다 실측한다 —
`프로젝트 에이전트 5/5`, `프로젝트 스킬 8/8`, `승인 게이트 연결됨`.
숫자가 안 맞으면 빨간색으로 뜨고, 그 실행 결과는 믿으면 안 된다.

## 승인 게이트

헤드리스 에이전트는 "사용자에게 물어보라"는 지시를 받아도 물어볼 창구가 없어서
임의로 답을 정하고 진행한다. 그래서 in-process MCP 서버로 툴 3개를 붙였다.

| 툴 | 쓰이는 곳 |
|---|---|
| `mcp__gate__ask_choice` | 소재 후보 선택, 카피 A/B |
| `mcp__gate__ask_approval` | QA 판정 후 진행, 릴스 착수, 기존 산출물 덮어쓰기 |
| `mcp__gate__ask_text` | 반려 사유, 수정 지시 |

호출되면 서버가 Promise를 붙잡은 채 SSE로 브라우저에 카드를 밀고,
사람이 누른 값을 `tool_result` 로 돌려준다. 시스템 프롬프트에
"텍스트로 질문하고 턴을 끝내지 마라"를 못 박아 뒀다 (`lib/gate.mjs`).

## 구조

```
server.mjs          Node 내장 http. 127.0.0.1 고정
lib/
  runner.mjs        query() 래핑. SDKMessage → UI 이벤트 정규화
  gate.mjs          승인 게이트 MCP 서버 + 프롬프트
  prompts.mjs       에이전트 카탈로그 · 프리셋 · 트리거 문장
  runs.mjs          실행 이력 · 스냅샷 · 복원
  artifacts.mjs     output/ 스캔 (PNG 규격 실측 포함)
  brief.mjs         팩트 원장 읽기 · 검증 · 쓰기
  paths.mjs         경로 해석 + 탈출 차단
public/             빌드 스텝 없음. ES 모듈 + CSS
.runs/              실행 이력 (gitignore)
.brief-backups/     원장 저장 전 백업 (gitignore)
```

## 안전 장치

- **127.0.0.1 바인딩 고정.** 에이전트가 이 레포에 파일을 쓰므로 외부 노출 없음
- **CSRF 토큰.** 아래 참조
- **동시 실행 1건.** 두 실행이 같은 `_workspace/` 를 밟으면 팩트 원장이 깨진다
- **실행 전 스냅샷.** `output/` 과 `_workspace/` 를 통째로 떠두고, 이력 화면에서 되돌릴 수 있다 (최근 20건 보관)
- **원장 쓰기 검증.** 출처 없는 사실, 편집 불가 필드(`card_skeleton`·`seo`·`landing`) 변경은 거부한다
- **파일 서빙 화이트리스트.** `output/`·`_workspace/`·`assets/` 밖은 403. 심볼릭 링크는 realpath로 정규화한 뒤 검사한다
- **`guard.py` 훅 유지.** 위험 명령 차단이 콘솔 실행에도 그대로 적용된다

### CSRF — 루프백 바인딩만으로는 부족하다

127.0.0.1 바인딩은 네트워크를 막을 뿐 **브라우저를 막지 못한다.** 운영자가 아무 웹페이지나
열어도 그 페이지가 `127.0.0.1:4173` 으로 POST를 보낼 수 있고, `POST /api/runs` 는
운영자의 자격증명으로 전체 툴 권한을 가진 에이전트를 띄운다 — 지시문은 공격자가 쓴다.
`<form enctype="text/plain">` 은 CORS 안전목록이라 프리플라이트도 없이 나간다.

그래서 **GET/HEAD 외의 모든 요청에 `x-console-token` 헤더를 요구한다.** 폼 전송은 커스텀
헤더를 붙일 수 없고, 붙이려면 이 서버가 응답하지 않는 프리플라이트를 타야 한다. 토큰은
`/api/meta` 로 내려주는데, CORS 헤더를 보내지 않으므로 교차 출처에서는 응답을 읽지 못한다.
`Origin` 헤더가 붙어 있으면 그것도 함께 검사한다.

토큰은 부팅 때마다 새로 발급되고 콘솔 시작 로그에 찍힌다. 브라우저는 자동으로 쓰므로
`curl` 등으로 **변경 요청**을 보낼 때만 직접 넣으면 된다:

```bash
curl -X POST localhost:4173/api/runs \
  -H "content-type: application/json" \
  -H "x-console-token: <시작 로그의 토큰>" \
  -d '{"agent":"card-producer","instruction":"..."}'
```

읽기(GET)는 토큰이 필요 없다 — 교차 출처에서 응답을 읽을 수 없어 유출 경로가 아니다.

## 루트에 package.json을 만들지 마라

`.claude/settings.json` 의 Stop 훅이 루트 `package.json` 을 감지하면
존재하지 않는 `npm run lint/build/test` 를 매 턴 실행해 실패한다.
콘솔의 의존성은 `web/package.json` 에 격리돼 있고,
에이전트는 항상 `cwd = 레포 루트` 로 돌기 때문에 훅 조건이 false로 유지된다.

## 환경변수

| 변수 | 기본값 | 용도 |
|---|---|---|
| `PORT` | `4173` | 포트 |
| `CAMPAIGN_MODEL` | `claude-opus-5` | 리드 모델 (서브에이전트는 각자 정의를 따른다) |
| `CAMPAIGN_MAX_TURNS` | `600` | 폭주 방지 상한 |
| `CAMPAIGN_SNAPSHOT_KEEP` | `20` | 스냅샷 보관 개수 |

인증은 별도 설정이 없다 — 로그인된 Claude Code 자격증명을 그대로 쓴다.

## 비용

하네스가 통째로 로드되므로(툴 103개·스킬 24개) 사소한 작업도 시스템 프롬프트가 크다.
단순 조회 1회가 **약 $0.7** 이었다. 카드 6장 제작이나 전체 검수는 그보다 훨씬 크다.
라이브 화면의 비용 표시와 이력의 누적치를 보고 판단하라.
한 번에 한 에이전트만 도는 것은 이 비용을 사람이 통제 가능한 단위로 쪼개는 장치이기도 하다.
